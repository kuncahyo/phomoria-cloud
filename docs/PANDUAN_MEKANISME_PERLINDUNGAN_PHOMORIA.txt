PANDUAN MEKANISME PERLINDUNGAN PHOMORIA
========================================

Repository : kuncahyo/phomoria-cloud
Branch     : feature/payment-protection-suspension
Framework  : Laravel 13
Database   : TIDAK DIUBAH oleh fitur ini

PENTING
-------
Mekanisme ini adalah penangguhan layanan yang terdokumentasi. Gunakan hanya
sesuai perjanjian pengerjaan/pembayaran dan kewenangan yang sah. Jangan
menggunakan token untuk menangguhkan instalasi yang tidak berada dalam
kewenangan Anda.

Mekanisme ini tidak menjalankan query database, migration, penghapusan data,
atau perubahan struktur tabel. Penanda penangguhan adalah sebuah file di
folder public.

1. FILE YANG DITAMBAHKAN
-----------------------
1) app/Http/Middleware/PaymentSuspensionMiddleware.php
   Memeriksa apakah file penanda ada. Jika ada, semua request Laravel
   ditangguhkan, kecuali dua endpoint kontrol yang harus tetap bisa dipakai
   untuk pemulihan.

2) app/Http/Controllers/System/PaymentProtectionController.php
   Menyediakan endpoint suspend dan resume. Keduanya memerlukan Bearer Token.

3) resources/views/payment-suspended.blade.php
   Halaman pemberitahuan untuk request browser ketika layanan ditangguhkan.

4) tests/Feature/PaymentProtectionTest.php
   Pengujian dasar untuk kondisi aktif, suspend, API, autentikasi, dan resume.

5) docs/PANDUAN_MEKANISME_PERLINDUNGAN_PHOMORIA.txt
   Panduan ini.

2. FILE YANG DIUBAH
-------------------
1) bootstrap/app.php
   Mendaftarkan PaymentSuspensionMiddleware sebagai global middleware Laravel.

2) routes/api.php
   Menambahkan:
   POST /api/payment-protection/suspend
   POST /api/payment-protection/resume

3) config/services.php
   Membaca token dari konfigurasi services.payment_protection.token.

4) .env.example
   Menambahkan contoh variabel PAYMENT_PROTECTION_TOKEN.

5) public/.htaccess
   Ketika file penanda ada, request untuk file statis yang biasanya langsung
   dilayani Apache juga diarahkan ke Laravel agar dapat ditangguhkan.
   Dua endpoint kontrol dan index.php dikecualikan dari rewrite khusus ini.
   Akses langsung ke file penanda ditolak oleh Apache.

3. CARA KONFIGURASI DI HOSTING
------------------------------
Tambahkan variabel berikut ke file .env di root Laravel:

PAYMENT_PROTECTION_TOKEN=GANTI_DENGAN_TOKEN_ACAK_PANJANG

Buat token acak yang panjang dan unik. Jangan masukkan token asli ke GitHub,
jangan kirim melalui chat publik, dan jangan menaruhnya di URL atau query
string. Simpan token di tempat aman. Setelah mengubah .env, jalankan:

php artisan config:clear
php artisan config:cache

Jika hosting tidak menggunakan config cache, config:clear cukup. Pastikan
folder public dapat ditulisi oleh proses PHP karena file penanda dibuat di
sana. Jangan mengubah permission menjadi 777.

4. CARA MENGAKTIFKAN PENANGGUHAN
-------------------------------
Kirim HTTP POST ke:

https://DOMAIN-ANDA/api/payment-protection/suspend

Header:

Authorization: Bearer TOKEN_RAHASIA_ANDA
Accept: application/json

Contoh cURL:

curl -X POST "https://DOMAIN-ANDA/api/payment-protection/suspend" ^
  -H "Authorization: Bearer TOKEN_RAHASIA_ANDA" ^
  -H "Accept: application/json"

Jika berhasil, server membuat file:

public/payment-suspended.txt

Respons sukses berisi status "suspended". Setelah file tersebut ada:
- halaman utama dan halaman web Laravel mengembalikan HTTP 503;
- halaman login, admin, dan galeri publik ikut ditangguhkan;
- API operasional dan webhook DOKU ikut ditangguhkan;
- request file statis melalui public yang melewati .htaccess juga diarahkan
  ke Laravel dan ditangguhkan;
- database dan seluruh data di dalamnya tidak disentuh.

5. CARA MENONAKTIFKAN / MEMULIHKAN
---------------------------------
Pilihan A - melalui endpoint resmi:

HTTP POST:
https://DOMAIN-ANDA/api/payment-protection/resume

Header:
Authorization: Bearer TOKEN_RAHASIA_ANDA
Accept: application/json

Contoh cURL:

curl -X POST "https://DOMAIN-ANDA/api/payment-protection/resume" ^
  -H "Authorization: Bearer TOKEN_RAHASIA_ANDA" ^
  -H "Accept: application/json"

Pilihan B - melalui Hostinger File Manager:
1) Buka File Manager hosting.
2) Masuk ke document root website, yaitu folder yang berisi index.php
   Laravel dan file .htaccess.
3) Hapus file payment-suspended.txt.
4) Muat ulang website.

Jika file penanda hilang, middleware mengizinkan request berjalan kembali.
Tidak perlu mengubah database, menjalankan migration, atau menghapus cache
Laravel untuk perubahan status ini.

6. BATASAN DAN PEMERIKSAAN
--------------------------
- Endpoint suspend/resume harus tetap dapat dijangkau agar pemulihan jarak
  jauh dimungkinkan. Endpoint tersebut tetap dilindungi Bearer Token.
- Jika token hilang atau salah, endpoint mengembalikan HTTP 401.
- Jika PAYMENT_PROTECTION_TOKEN belum diatur, endpoint menolak permintaan.
- Jika PHP tidak memiliki izin menulis ke folder public, suspend gagal dan
  mengembalikan HTTP 500; tidak boleh dianggap berhasil.
- Penangguhan request file statis bergantung pada Apache mod_rewrite dan
  konfigurasi .htaccess yang aktif. Jika hosting menggunakan Nginx atau
  konfigurasi proxy/CDN yang menyajikan file dari cache, aturan server/CDN
  tambahan mungkin diperlukan.
- File yang sudah tersimpan di cache browser, CDN, atau layanan eksternal
  tidak dapat ditarik kembali oleh middleware Laravel.
- Worker/queue yang sudah berjalan di proses terpisah tidak otomatis berhenti
  hanya karena request web ditangguhkan. Jangan menganggap ini sebagai
  penghentian proses server/worker.
- Selalu uji di staging sebelum mengaktifkan di hosting produksi.

7. PENGUJIAN
------------
Di komputer lokal, atur token di environment testing atau konfigurasi test,
lalu jalankan:

php artisan test --filter=PaymentProtectionTest

Uji manual:
1) Pastikan public/payment-suspended.txt belum ada; website harus aktif.
2) Kirim endpoint suspend dengan token yang benar.
3) Buka halaman utama, /login, /admin, /gallery, dan endpoint API; semuanya
   harus menerima status penangguhan.
4) Pastikan endpoint resume tetap dapat dipanggil ketika suspended.
5) Pastikan file payment-suspended.txt terhapus dan website kembali aktif.
6) Pastikan tidak ada migration atau perubahan database yang dijalankan.

8. PENGHAPUSAN PERMANEN SETELAH KEWAJIBAN SELESAI
------------------------------------------------
Lakukan hanya setelah dipastikan mekanisme tidak lagi diperlukan dan versi
bersih telah diuji. Buat backup source code terlebih dahulu.

A. Hapus file yang ditambahkan:
- app/Http/Middleware/PaymentSuspensionMiddleware.php
- app/Http/Controllers/System/PaymentProtectionController.php
- resources/views/payment-suspended.blade.php
- tests/Feature/PaymentProtectionTest.php
- docs/PANDUAN_MEKANISME_PERLINDUNGAN_PHOMORIA.txt

B. Kembalikan bootstrap/app.php:
Hapus baris import:
use App\Http\Middleware\PaymentSuspensionMiddleware;

Hapus pendaftaran middleware berikut dari callback withMiddleware:
$middleware->append(PaymentSuspensionMiddleware::class);

Jangan menghapus middleware Laravel lain.

C. Kembalikan routes/api.php:
Hapus import:
use App\Http\Controllers\System\PaymentProtectionController;

Hapus dua route POST di dalam prefix payment-protection:
POST /payment-protection/suspend
POST /payment-protection/resume

Jangan mengubah route API lain, termasuk webhook DOKU.

D. Kembalikan config/services.php:
Hapus blok konfigurasi:
'payment_protection' => [
    'token' => env('PAYMENT_PROTECTION_TOKEN'),
],

E. Kembalikan .env.example:
Hapus baris PAYMENT_PROTECTION_TOKEN=.

F. Kembalikan public/.htaccess:
Hapus blok khusus yang dimulai dengan komentar:
# Payment-protection suspension marker
Blok tersebut mencakup kondisi RewriteCond untuk payment-suspended.txt,
pengecualian endpoint kontrol, RewriteRule ke index.php, dan aturan Files
yang menolak akses langsung ke file marker. Pertahankan aturan Laravel
lainnya yang sudah ada.

G. Bersihkan konfigurasi hosting:
- Hapus PAYMENT_PROTECTION_TOKEN dari .env hosting.
- Hapus public/payment-suspended.txt jika masih ada.
- Jalankan php artisan config:clear lalu php artisan config:cache.

H. Verifikasi:
- Cari seluruh source untuk kata PaymentSuspensionMiddleware,
  PaymentProtectionController, payment-protection, payment-suspended.txt,
  dan PAYMENT_PROTECTION_TOKEN.
- Pastikan tidak ada referensi kode yang tertinggal.
- Jalankan test suite.
- Pastikan route payment-protection tidak lagi terdaftar.
- Pastikan website, login, CMS, galeri, API, upload, dan webhook DOKU
  berjalan normal.

9. CATATAN PENTING TENTANG NOMOR BARIS
--------------------------------------
Panduan ini menggunakan nama file, potongan kode, dan konteks perubahan,
bukan nomor baris tetap. Nomor baris berubah setiap kali source code diedit.
Saat penghapusan, cari teks yang disebutkan pada file terkait dan hapus hanya
blok fitur ini. Jangan mengganti seluruh file dengan salinan lama karena
dapat menghilangkan perubahan fitur lain yang dibuat setelah branch ini.

10. STATUS DATABASE
-------------------
Fitur ini tidak menambah migration dan tidak mengubah skema database.
Controller dan middleware tidak menggunakan model atau query database.
File marker berada di public/payment-suspended.txt.
