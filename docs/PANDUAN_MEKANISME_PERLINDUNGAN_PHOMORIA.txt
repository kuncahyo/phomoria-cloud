PANDUAN MEKANISME PERLINDUNGAN PHOMORIA
========================================

Repository : kuncahyo/phomoria-cloud
Branch     : feature/payment-protection-suspension
Framework  : Laravel 13
Lingkungan : Hostinger, Laravel di phomoria.com/sub
Database   : TIDAK DIUBAH oleh fitur ini

PENTING
-------
Mekanisme ini adalah penangguhan layanan yang terdokumentasi. Gunakan hanya
sesuai perjanjian pengerjaan/pembayaran dan kewenangan yang sah. Jangan
menggunakan token untuk menangguhkan instalasi yang tidak berada dalam
kewenangan Anda.

Mekanisme ini tidak menjalankan query database, migration, penghapusan data,
atau perubahan struktur tabel. Penanda penangguhan adalah file di document
root aplikasi web, terpisah dari source code Laravel.

STRUKTUR HOSTING YANG DITARGETKAN
--------------------------------
Source Laravel:
  /home/AKUN/domains/phomoria.com/phomoria-cloud

Document root website Laravel saat ini:
  /home/AKUN/domains/phomoria.com/public_html/sub

Entry point:
  public_html/sub/index.php

Entry point tersebut memuat:
  phomoria-cloud/vendor/autoload.php
  phomoria-cloud/bootstrap/app.php

Karena website berjalan di /sub, file .htaccess yang mengatur request aktif
adalah public_html/sub/.htaccess, BUKAN phomoria-cloud/public/.htaccess.
Jangan mengganti atau menghapus file .htaccess website utama di
public_html/.htaccess.

1. FILE YANG DITAMBAHKAN
-----------------------
1) app/Http/Middleware/PaymentSuspensionMiddleware.php
   Memeriksa file penanda berdasarkan PAYMENT_PROTECTION_MARKER_PATH. Jika
   ada, request Laravel ditangguhkan, kecuali dua endpoint kontrol.

2) app/Http/Controllers/System/PaymentProtectionController.php
   Menyediakan endpoint suspend dan resume. Keduanya memerlukan Bearer Token
   dan membuat/menghapus file penanda pada lokasi yang dikonfigurasi.

3) resources/views/payment-suspended.blade.php
   Halaman pemberitahuan untuk request browser ketika layanan ditangguhkan.

4) tests/Feature/PaymentProtectionTest.php
   Pengujian dasar untuk kondisi aktif, suspend, API, autentikasi, dan resume.
   Pengujian memakai file penanda sementara di public aplikasi testing, bukan
   file penanda hosting.

5) docs/PANDUAN_MEKANISME_PERLINDUNGAN_PHOMORIA.txt
   Panduan ini.

2. FILE YANG DIUBAH
-------------------
1) bootstrap/app.php
   Mendaftarkan PaymentSuspensionMiddleware sebagai global middleware Laravel.

2) routes/api.php
   Menambahkan:
   POST /api/payment-protection/suspend
   POST /api/payment-protection/resume

3) config/services.php
   Membaca token dan lokasi file penanda dari konfigurasi:
   services.payment_protection.token
   services.payment_protection.marker_path

4) .env.example
   Menambahkan contoh variabel:
   PAYMENT_PROTECTION_TOKEN
   PAYMENT_PROTECTION_MARKER_PATH

5) public/.htaccess
   Tetap memakai aturan Laravel standar. File ini bukan .htaccess yang aktif
   untuk website phomoria.com/sub saat ini. Aturan khusus hosting /sub harus
   ditambahkan pada public_html/sub/.htaccess secara manual seperti bagian 4.

3. KONFIGURASI DI HOSTINGER
---------------------------
A. Buat token rahasia dari SSH. Perintah ini hanya mencetak token, tidak
   mengubah file:

   php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"

   Simpan token tersebut di tempat aman. Jangan masukkan token asli ke GitHub,
   chat publik, URL, atau query string.

B. Tentukan path absolut file penanda. Untuk struktur hosting saat ini, file
   penanda akan ditempatkan di:

   /home/AKUN/domains/phomoria.com/public_html/sub/payment-suspended.txt

   Ganti AKUN dengan nama akun hosting sebenarnya. Untuk memastikan path,
   jalankan:
   cd /home/AKUN/domains/phomoria.com/public_html/sub
   pwd

   Tambahkan /payment-suspended.txt pada hasil pwd.

C. Edit file .env di root phomoria-cloud. Tambahkan dua baris berikut:

   PAYMENT_PROTECTION_TOKEN=ISI_DENGAN_TOKEN_ACAK
   PAYMENT_PROTECTION_MARKER_PATH=/PATH/ABSOLUT/KE/public_html/sub/payment-suspended.txt

   Jangan memakai tanda kutip kecuali diperlukan oleh format .env. Jangan
   mengunggah .env ke GitHub.

D. Setelah konfigurasi disimpan, dari root phomoria-cloud jalankan:

   php artisan config:clear
   php artisan config:cache

   Pastikan PHP dapat menulis dan menghapus file di folder
   public_html/sub. Jangan mengubah permission menjadi 777.

E. Jangan mengaktifkan suspend sebelum aturan .htaccess bagian 4 sudah dipasang
   dan diuji. Tanpa aturan itu, file statis yang sudah ada dapat tetap dilayani
   langsung oleh web server walaupun middleware Laravel menangguhkan request
   dinamis.

4. ATURAN .HTACCESS UNTUK WEBSITE /SUB
--------------------------------------
File yang harus diedit:
  /home/AKUN/domains/phomoria.com/public_html/sub/.htaccess

JANGAN mengedit:
  /home/AKUN/domains/phomoria.com/public_html/.htaccess
  phomoria-cloud/public/.htaccess

Sebelum mengedit, buat salinan:
  cp ../public_html/sub/.htaccess ../public_html/sub/.htaccess.backup-payment-protection

Perintah tersebut dijalankan dari root phomoria-cloud. Pastikan file backup
berhasil dibuat sebelum melanjutkan.

Di dalam public_html/sub/.htaccess, cari baris:
  RewriteEngine On

Tepat setelah baris tersebut, tambahkan blok ini:

    # Payment-protection suspension marker for the /sub deployment.
    # The marker is stored in the /sub document root.
    RewriteCond %{DOCUMENT_ROOT}/sub/payment-suspended.txt -f
    RewriteCond %{REQUEST_URI} !^/sub/api/payment-protection/(suspend|resume)$ [NC]
    RewriteCond %{REQUEST_URI} !^/sub/index\.php$ [NC]
    RewriteRule ^ index.php [L]

Di bagian paling bawah file, setelah blok </IfModule>, tambahkan:

    # Do not expose the suspension marker as a downloadable file.
    <Files "payment-suspended.txt">
        Require all denied
    </Files>

Pertahankan semua aturan .htaccess yang sudah ada. Jangan mengganti seluruh
file dengan contoh di atas. Dua endpoint yang dikecualikan tetap harus
diteruskan ke index.php Laravel oleh aturan front-controller yang sudah ada.

PENTING: pengecualian .htaccess memakai URL publik dengan prefix /sub.
Middleware Laravel mengecualikan path route tanpa prefix deployment, yaitu
api/payment-protection/suspend dan api/payment-protection/resume.

5. CARA MENGAKTIFKAN PENANGGUHAN
-------------------------------
Endpoint publik untuk website yang sekarang:

POST https://phomoria.com/sub/api/payment-protection/suspend

Header:
  Authorization: Bearer TOKEN_RAHASIA_ANDA
  Accept: application/json

Contoh cURL dari terminal:

curl -X POST "https://phomoria.com/sub/api/payment-protection/suspend" \
  -H "Authorization: Bearer TOKEN_RAHASIA_ANDA" \
  -H "Accept: application/json"

Jika berhasil, server membuat file:

  public_html/sub/payment-suspended.txt

Respons sukses berisi status "suspended". Setelah file tersebut ada:
- halaman utama dan halaman web Laravel mengembalikan HTTP 503;
- halaman login, admin, dan galeri publik ikut ditangguhkan;
- API operasional dan webhook DOKU ikut ditangguhkan;
- file statis di bawah /sub yang diminta melalui web server juga diarahkan
  ke Laravel lalu ditangguhkan;
- dua endpoint payment-protection tetap dapat dipanggil;
- database dan seluruh data di dalamnya tidak disentuh.

6. CARA MENONAKTIFKAN / MEMULIHKAN
---------------------------------
Pilihan A - melalui endpoint resmi:

POST https://phomoria.com/sub/api/payment-protection/resume

Header:
  Authorization: Bearer TOKEN_RAHASIA_ANDA
  Accept: application/json

Contoh cURL:

curl -X POST "https://phomoria.com/sub/api/payment-protection/resume" \
  -H "Authorization: Bearer TOKEN_RAHASIA_ANDA" \
  -H "Accept: application/json"

Pilihan B - melalui Hostinger File Manager:
1) Buka File Manager hosting.
2) Masuk ke public_html/sub.
3) Hapus file payment-suspended.txt.
4) Muat ulang website.

Pilihan C - melalui SSH:
  rm /PATH/ABSOLUT/KE/public_html/sub/payment-suspended.txt

Hapus hanya file penanda tersebut. Jangan menghapus folder sub atau file lain.

Jika file penanda hilang, middleware mengizinkan request berjalan kembali.
Tidak perlu mengubah database, menjalankan migration, atau menghapus cache
Laravel untuk perubahan status ini.

7. PENGUJIAN SEBELUM DIPAKAI
----------------------------
Jalankan pengujian otomatis dari root project:

  php artisan test --filter=PaymentProtectionTest

Pengujian otomatis harus memakai environment testing dan marker sementara.
Jangan jalankan test suite ketika ada file penanda produksi aktif.

Setelah deploy ke hosting dan sebelum suspend sungguhan, uji dengan urutan:
1) Pastikan file payment-suspended.txt belum ada.
2) Pastikan website /sub, login, CMS, dan galeri dapat dibuka.
3) Pastikan endpoint suspend dengan token salah mengembalikan HTTP 401.
4) Pastikan endpoint suspend dengan token benar membuat marker dan
   mengembalikan status suspended.
5) Ketika marker ada, uji halaman web, satu API operasional, dan satu file
   statis di /sub. Semuanya harus menerima HTTP 503.
6) Saat masih suspended, panggil endpoint resume dengan token benar.
   Endpoint harus tetap merespons status active.
7) Pastikan marker terhapus dan website kembali normal.

Lakukan pengujian terkontrol dengan file atau halaman yang aman. Jangan
gunakan file installer/release pelanggan sebagai objek uji unduhan.

8. BATASAN DAN PEMERIKSAAN
--------------------------
- Endpoint suspend/resume harus tetap dapat dijangkau agar pemulihan jarak
  jauh dimungkinkan. Endpoint tersebut tetap dilindungi Bearer Token.
- Jika token hilang atau salah, endpoint mengembalikan HTTP 401.
- Jika PAYMENT_PROTECTION_TOKEN belum diatur, endpoint menolak permintaan.
- PAYMENT_PROTECTION_MARKER_PATH harus menunjuk ke lokasi yang sama dengan
  file yang diperiksa oleh aturan .htaccess.
- Jika PHP tidak memiliki izin menulis/menghapus file penanda, endpoint
  mengembalikan HTTP 500; jangan menganggap suspend/resume berhasil.
- Pengalihan file statis bergantung pada Apache/LiteSpeed dan mod_rewrite.
  Jika ada CDN atau cache proxy, konten yang sudah tersimpan di cache mungkin
  tetap dapat disajikan sampai cache tersebut kedaluwarsa/dibersihkan.
- File yang sudah tersimpan di cache browser atau layanan eksternal tidak
  dapat ditarik kembali oleh middleware.
- Worker/queue yang sudah berjalan di proses terpisah tidak otomatis berhenti
  hanya karena request web ditangguhkan.
- Selalu uji di lingkungan terpisah atau pada waktu pemeliharaan yang disetujui
  sebelum memakai mekanisme ini untuk penangguhan sungguhan.
